# /content-new-brand - a new brand from a brand guide file

Arguments: `$ARGUMENTS` (the new brand's name, then the source file or folder).

**First load the `video-pipeline` skill** (folders, running commands, golden rules). Read `brands/README.md` and the template files in `brands/_template/` so you know every field you have to fill. This skill only sets the process: everything about the brand comes from their file and their answers, never from another brand.

## 0. inputs

- **name**: lowercase letters, numbers, `-`, `_` (eg `mia`, `wornbybeth`). missing → ask. `brands/<name>/` already exists → stop and ask whether to update it instead (then edit in place, never overwrite their files)
- **source**: a file or folder in `inputs/brand-guides/` (list it with `ls`; `python -m engine inputs` only lists video clips), or any path they give. missing → ask for it; if they have none, run the full interview from the template headings instead
- the source is read only (it's in `inputs/`): never edit, move or delete it

## 1. read the whole source

| type | how |
|---|---|
| `.pdf` | the Read tool, in page ranges (20 pages max per call) until you've seen every page, including the visual pages (colour swatches, type specimens, example posts) |
| `.md`, `.txt`, `.csv` | Read |
| `.docx`, `.pptx` | pull the text with python's `zipfile` (`word/document.xml`, `ppt/slides/*.xml`), and extract `word/media/*` / `ppt/media/*` images to `work/brand-<name>/` and Read them |
| images (`.png`, `.jpg`, `.webp`, `.heic`) | Read each one. screenshots of example posts tell you caption placement, case, font weight, accent use and pacing cues |
| a folder | all of the above for every file in it |
| a `.cube` / `.3dl` LUT or capcut / lightroom preset screenshot | see step 5 |

Make notes as you go: every fact with where it came from (page / file), so you can tell them what you took from the guide and what you assumed.

## 2. make the brand folder

```
.venv/bin/python -m engine brand new <name> --style <editorial|playful|butter>
```

Pick the generic look closest to the guide (`assets/styles/README.md` explains the fields; `editorial` = clean / bold, `playful` = bright / loud, `butter` = calm / soft). This copies `brands/_template/` to `brands/<name>/`.

## 3. brand.md

Fill every heading in `brands/<name>/brand.md` from the source: who they are and who they talk to, tone (with example phrases from the guide), how they film, take rules, captions (case, names that keep capitals, spellings, words to avoid), pacing, b-roll, fonts and colours (hex codes), colour grade, accounts / handles, defaults per format, open items. Add a line under the title: `made from inputs/brand-guides/<file> on <date>`.

- write it the way the other brand guides read: short plain lines, no em dashes, british spelling
- facts the guide doesn't cover go under "open items" as questions, not guesses
- don't copy marketing copy wholesale: pull out the rules an editor needs

## 4. style.json

Map the guide onto `brands/<name>/style.json` (field meanings in `assets/styles/README.md`):

- `font` / `hook_font` / `keyword_font`: the guide's fonts. the font file must be installed or in `assets/fonts/` (shared by every brand). not there → ask them for the .ttf / .otf; until then use the nearest installed font and say so (fallback Arial)
- colours: caption, keyword / highlight, hook box, badge, takeover, from the guide's palette (exact hex)
- `lowercase`, `keep_caps` (brand names, product names, handles), `caption_mode`, `words_per_caption`, `spacing`, `caption_position`, `hook_box`, zoom amounts: from the guide's examples, else keep the template's value and list it as an assumption
- check readability, and fix any pair under 4.5:1 by darkening text / deepening the background (never by dropping the check):
  ```
  .venv/bin/python -m engine contrast --brand <name>
  ```

## 5. grade.json and LUTs (use the optimised path only)

`brands/<name>/grade.json` holds capcut-style numbers (`temp`, `tint`, `saturation`, `whites`, `blacks`, `clarity`, `hsl`, `strength`, `neutral_blacks`). Fill it from the guide or their usual capcut settings, set `"enabled": true`. Nothing in the guide → ask for their capcut numbers, or leave `"enabled": false` and add it to open items.

**Every LUT for a brand is generated by the engine's optimised grade path, never by hand.** The engine turns grade.json into the colour table itself (`engine/core/grade.py`):

- `grade_filter()` → `build_lut()`: the colour steps from `colour_chain()` are run once over a 16-bit identity image (`haldclutsrc` level `LUT_LEVEL = 6`, a 36x36x36 table, `rgb48le`) and saved as `work/_grade/grade_<hash>.cube`
- renders apply it in one pass with `lut3d=...:interp=tetrahedral` (about 2.5x faster than the five-filter chain, matches it to ~48 dB)
- clarity is not a colour change, so it stays out of the table: a separate `unsharp=7:7` after it (`clarity_filter()`)
- the table is cached by a hash of the grade, so a changed grade.json makes a new one automatically; nothing to delete or rebuild by hand

So, when making a brand:

- don't write `.cube` files, don't build an 8-bit table (banding), don't change `LUT_LEVEL`, don't put clarity into a table, and don't render or preview with the raw `colour_chain()` filters (that's only for comparing while tuning)
- generate and check the brand's table with a test clip (ask them for one in `inputs/talking-head/`):
  ```
  .venv/bin/python -m engine grade <clip> --brand <name> [--at <sec>]
  ```
  this builds the optimised table and saves `output/<name>/grade/<date>_<time>_<clip>/<clip>_grade_compare.jpg` (left before, right after). too strong or weak → adjust the `strength` values in grade.json, not their slider numbers. measure a neutral (eg black clothing) before/after as in `video-pipeline/references/checks.md`
- **the guide ships its own LUT** (`.cube` / `.3dl`) or a preset screenshot: the engine doesn't load external LUT files. match it with grade.json numbers instead (apply their LUT to a test frame with ffmpeg `lut3d` only to compare, then tune the numbers until the engine's grade compare matches it), and keep their file in `inputs/brand-guides/` for reference. if the match isn't close enough, say so and offer to add external-LUT support to `engine/core/grade.py`, applied through the same tetrahedral `lut3d` pass with clarity kept separate

## 6. effects.md

Keep the template's effects (they map to the engine's treatments). Add any named looks from the guide (eg "pink flash card", "lower third") with how to recreate them from existing treatments, motions and style settings. Anything the engine can't do → say so in effects.md and in open items, and offer to build it.

## 7. b-roll

Ask them to copy the brand's b-roll into `brands/<name>/broll/` (subfolders by theme help). Then:
```
.venv/bin/python -m engine broll index --brand <name>
```
and fill `description`, `tags`, `good_for` for every clip in `brands/<name>/broll/library.json` (see the talking-head reference). No b-roll yet → note it in open items.

## 8. fill the gaps, then confirm

1. show them a short summary: what you took from the guide (with page / file), what you assumed, and the open questions
2. ask the open questions one at a time, conversationally (the brand interview, but only for gaps). update brand.md / style.json / grade.json with each answer
3. `python -m engine brand list` shows the brand with nothing missing; `python -m engine contrast --brand <name>` passes; the grade compare looks right to them
4. offer a draft test edit of a clip in their style (`--draft`) so they can see the look before a real job
